## 通知实现补充

开关通过独立存储即时保存，Android 沿用 AtomicFile；完整快照仍异步落盘。
冷启动与后台读取合并最新开关，避免旧快照恢复已关闭的提醒。关闭时仅取消明日提醒自己的通知和闹钟，
发送前后再次核对当前状态；不取消 Live 通知。

广播通过 `goAsync` 在后台执行，校验触发日期、20:30 时间窗口、明日课程、通知权限和频道状态。
仅在系统通知调用成功且复核仍有效后保存当日发送记录，重复广播不重复提醒；失败不消耗当日记录。
采用一次性闹钟并在处理后安排下一天，启动、系统时间或时区变化及应用升级时恢复调度。
有精确闹钟权限时使用精确调度，否则回退系统非精确调度，实际通知可能延迟；跨日过期广播不补发。

通知权限请求受 Activity 生命周期及请求中状态约束，避免启动与 Compose 同时重复请求；用户显式开启开关可再次发起请求。
