## 集成时额外修正

- 第三阶段脚本在声明的基线上有两处相同锚点，却要求仅匹配一次。调整集成副本的匹配数，
  并移除由此在登录通道切换函数中产生的重复 `settings` 参数。
- 服务启动由刷新循环首帧统一发布，保留参数、时间和刷新点来自同一帧的处理；
  旧通知的删除回调用课程和阶段共同区分 PendingIntent。
- 系统闹钟只安排提醒点和上下课边界，移除 `setAlarmClock`；应用和服务的分钟刷新仍使用
  独立的绝对刷新点，发布耗时跨过边界时立即校正。
- 厂商构建错误交给共享引擎处理，按 HyperOS 私有协议、Android 原生、普通通知重新构造。
  成功后立即停止，使用同一个通知 ID。
- 原补丁只在服务中限制发送重试。本次把失败计数持久化到共同发送入口，应用、广播、服务
  共用每课程最多两次重试，且不超过课程结束时间。权限、渠道关闭和主动划掉不触发重试。
- Cookie 的有效 `Max-Age` 优先于 `Expires`，新增持久化与重新加载回归测试。
- CI 的每条 Gradle 命令传入 `-Dorg.gradle.java.home="$JAVA_HOME"`，避免使用本机写死的 JDK 路径。
- 版本名称、代码和 README 同步更新；本地压缩包、下载标记和集成工作目录不纳入 Git。

  [官方 Live Updates 文档](https://developer.android.com/develop/ui/views/notifications/live-update)。
